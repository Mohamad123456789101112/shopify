# BLY

مشروع Next.js تم فكّه في جذر المستودع، وجاهز للبناء بدون `DATABASE_URL`.

## الرفع على Vercel

1. استورد المستودع واختَر الفرع الذي يحتوي على الملفات المفكوكة والتعديلات.
2. **Root Directory:** جذر المستودع (`.`)، وليس ملف ZIP.
3. **Framework Preset:** Next.js.
4. **Build Command:** `npm run build`، واترك Output Directory افتراضيًا.
5. لا تحتاج إضافة أي Environment Variables لعرض الموقع. اضغط Deploy.

بدون قاعدة بيانات تعمل الصفحات التعريفية والأسعار والقوالب وصفحات الدخول.
تظهر رسالة توضيحية بصفحات الحسابات، وتظل عمليات التسجيل والدخول والطلبات
ورفع الملفات وإدارة المتاجر معطّلة؛ لا يتم الادعاء بحفظ أي بيانات.
المتاجر غير الموجودة ترجع 404، والمسارات المحمية تحول الزائر لتسجيل الدخول.
واجهات API التي تعتمد على قاعدة البيانات ترجع JSON واضحًا بحالة 503،
وليس خطأ داخليًا غير معالج. `/api/health` يرجع `ok: true` مع
`database: "not_configured"` و`mode: "website-only"` في هذا الوضع.

## التشغيل والتحقق محليًا

يتطلب Node.js متوافقًا مع Next.js 16 (استخدم Node.js 22 أو أحدث).

```sh
npm ci
npm run build
npm start -- --hostname 0.0.0.0
# في نافذة أخرى، مع تشغيل الموقع بدون DATABASE_URL:
npm run test:no-db
```

لتطوير الواجهة: `npm run dev -- --hostname 0.0.0.0`.

## قاعدة البيانات اختيارية للنشر، مطلوبة للتجارة الفعلية

لتمكين الحسابات والمتاجر والطلبات لاحقًا، أضف `DATABASE_URL` كمتغير سري
على الخادم، ثم جهّز جداول PostgreSQL وسياسات الأمان والبيانات المطلوبة، وأعد النشر.
لا تضع رابط اتصال أو كلمة مرور داخل الكود أو في متغير `NEXT_PUBLIC_*`.
إضافة الرابط وحده لا تنشئ الجداول تلقائيًا. سكربت البذر المرفق من الأرشيف
مخصص لبيانات التجربة؛ راجعه قبل استخدامه، ولا تشغّله على قاعدة إنتاج.
