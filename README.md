# BLY Commerce

منصة متاجر Next.js 16 + PostgreSQL، بواجهة إدارة احترافية مستوحاة من أسلوب لوحات التجارة، وهوية BLY مستقلة (ليست Shopify ولا متصلة بخدماتها).

## الصفحات

- `/demo`: معاينة عامة للوحة التحكم ببيانات توضيحية، بدون حساب.
- `/signup` و`/login`: حسابات حقيقية، كلمات مرور scrypt، وجلسات HttpOnly محفوظة كقيم مجزأة في قاعدة البيانات.
- `/setup`: إعداد اسم المتجر، العملة، القالب، والمنتج الأول.
- `/dashboard`: تقارير حقيقية، فترات 7/30/90 يومًا، منتجات، طلبات، عملاء، إعدادات، إشعارات، وكوبونات بحسب الخطة.
- `/dashboard/builder`: تخصيص القالب ونشره.
- `/store/{slug}`: متجر منشور، سلة، إتمام طلب، وتتبع برمز الطلب والهاتف.

## تفعيل قاعدة البيانات على Vercel

1. افتح مشروع **bly-shopify → Settings → Environment Variables**.
2. ضع رابط PostgreSQL الحقيقي في **`DATABASE_URL`**، وحدد **Production** (وPreview إذا احتجته).
3. استخدم اتصال مالك قاعدة البيانات بصلاحية `BYPASSRLS` (أو superuser) وإنشاء الجداول والأدوار وتفعيل `pgcrypto` وRLS. في Supabase استخدم **Session pooler، منفذ 5432** من نافذة Connect، مع إعدادات TLS التي يوفرها المزود. اتصالات المستخدم محدود الصلاحيات أو رابط HTTPS الخاص بواجهة Supabase ليست بديلًا لرابط PostgreSQL.
4. نفّذ **Redeploy** للنسخة من الفرع `arena/2beab975-shopify`. فرع `main` الأصلي يحتوي الأرشيف فقط؛ لا تنشره قبل إدخال ملفات التطبيق إليه.
5. افتح `/api/health`. عند نجاح الإعداد يرجع `database: "connected"`.
6. أنشئ حسابك من `/signup` وأكمل `/setup` ثم أضف منتجاتك.

**تهيئة الجداول تلقائية عند أول طلب يحتاج الداتابيز**: migration داخل transaction مع advisory lock لمنع التعارض بين نسخ Vercel، ثم تفعيل الأدوار والسياسات والدوال. لا يحدث اتصال بالداتابيز أثناء build ولا تُنشأ حسابات تجريبية أو مدير افتراضي. تهيئة قاعدة جديدة قد تجعل أول طلب أبطأ قليلًا. يفضّل قاعدة/مشروع مخصص لهذه المنصة مع نسخة احتياطية لأي بيانات قائمة.

يمكن تشغيل التهيئة يدويًا قبل استقبال المستخدمين:

```sh
cp .env.example .env
# أضف الرابط محليًا داخل .env (الملف مستبعد من Git)
npm ci
npm run db:migrate
```

لا تشارك الرابط في الدردشة أو Git، ولا تسمّه `NEXT_PUBLIC_DATABASE_URL`. لا يوجد رابط وهمي أو كلمة مرور إنتاج داخل الكود. الـ pool محدود إلى 5 اتصالات لكل نسخة؛ اضبط سعة مزودك مع نمو الاستخدام.

### بدون DATABASE_URL

تبقى الواجهة العامة والمعاينة متاحتين. تعرض الحسابات تنبيهًا، والواجهات المعتمدة على الداتابيز ترجع 503 بصيغة JSON. `/api/health` يرجع `mode: "website-only"` بوضوح، ولا يدّعي اتصالًا غير موجود.

## استعادة كلمة المرور

التسجيل والدخول لا يحتاجان إلا قاعدة البيانات. **إرسال بريد الاستعادة** يحتاج أيضًا:

```dotenv
APP_URL=https://bly-shopify.vercel.app
RESEND_API_KEY=...
EMAIL_FROM=Your Brand <verified-sender@your-domain.example>
```

يجب توثيق المرسل لدى مزود البريد. لا تُعرض رسالة إرسال ناجح إذا لم تُضبط الخدمة. الروابط تُحفظ كقيم SHA-256، تنتهي بعد 30 دقيقة، تُستخدم مرة واحدة فقط، وتغيير كلمة المرور يلغي كل الجلسات. تم اختبار توليد/استهلاك الرموز محليًا؛ التسليم الفعلي للبريد يتطلب إعداد المزود ولم يُختبر دون مفاتيحه.

## حدود التكاملات الحالية

- الدفع عند الاستلام يعمل. Vodafone Cash وInstaPay تحويلات يدوية مع مرجع ومراجعة؛ لا يوجد تحصيل بطاقات تلقائي أو ربط بشركة شحن أو احتساب ضرائب آلي.
- طلب ترقية الخطة يُراجع يدويًا بواسطة مالك المنصة. لا تُنشأ وجهات تحويل وهمية. يجب إعداد بيانات التحويل وتعيين مالك عبر قاعدة البيانات من حساب موثوق قبل بيع الاشتراكات.
- الحملات تُحفظ كمسودات؛ إرسال Email/WhatsApp لم يُربط بمزود تسويق. الدومينات المخصصة موضحة كخدمة غير متصلة، وليست إعداد DNS يعمل تلقائيًا.
- المنتجات تدعم اللون والمقاس كخصائص؛ المخزون حاليًا على مستوى المنتج وليس مخزونًا مستقلًا لكل تركيبة variants.
- رفع الصور الخاصة بالتاجر متاح حتى 4MB للمنتج/الإيصال لتوافق حد طلبات Vercel. التخزين حاليًا PostgreSQL، وليس خدمة ملفات مستقلة.
- واجهة الإدارة الأساسية والحسابات تدعمان العربية وRTL، وبعض شاشات الإدارة التفصيلية ما زالت بالنص الإنجليزي.

## التشغيل والاختبارات

استخدم Node.js 22 أو أحدث.

```sh
npm ci
npm run dev -- --hostname 0.0.0.0
npm run build
npm run typecheck
npm run lint
```

فحص وضع عدم وجود قاعدة بيانات، مع تشغيل production server بدون المتغير:

```sh
npm start -- --hostname 0.0.0.0
npm run test:no-db
```

اختبارات التجارة تكتب بيانات اختبار ثم تحذف حساباتها. **لا تشغّلها على الإنتاج**. لقاعدة PostgreSQL محلية منفصلة (يشترط مستخدم نظام غير root):

```sh
node scripts/test-database.mjs
# في نافذة أخرى:
DATABASE_URL=postgresql://postgres:local-integration-only@127.0.0.1:55432/bly_test npm start -- --hostname 0.0.0.0 --port 3001
# في نافذة ثالثة:
TEST_DATABASE_URL=postgresql://postgres:local-integration-only@127.0.0.1:55432/bly_test npm run test:commerce
```

تغطي الاختبارات التسجيل، التكرار، الدخول، الجلسات، إعداد المتجر، المنتجات، عزل التجار، الشراء بسعر السيرفر وخصم المخزون، الكوبونات، إعدادات الشحن، نشر الصور، RLS، CSRF، تغيير كلمة المرور وإلغاء الجلسات. اختُبرت النسخة أيضًا بمتصفح على الكمبيوتر والموبايل والبحث السريع والعربية.

**تنبيه:** `scripts/seed.mjs` ملف قديم من الأرشيف ببيانات تجريبية؛ لا تشغّله على قاعدة إنتاج. التطبيق والـ migration لا يستدعيانه.
